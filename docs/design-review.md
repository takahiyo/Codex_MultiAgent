# マルチエージェントによる設計レビュー（2026-10-15）

## 設計の位置付け

このリポジトリが配布するのはグローバル`AGENTS.md`の運用方針です。委任ツールはCodex実行環境が提供します。方針の導入、ファイル一致、委任の起動・完了、実際のモデル適用値は別々に確認します。config.tomlや認証情報を共有して機能を強制する設計にはしません。

[公式AGENTS.md説明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)では、グローバル方針のほか、overrideとプロジェクト側の指示も関係します。[公式サブエージェント説明](https://learn.chatgpt.com/docs/agent-configuration/subagents)では、子は親の権限を引き継ぎ、読み取り専用の依頼文自体が別のサンドボックスを作るわけではないことが説明されています。このため、担当・許可操作・検証の責任を主担当が明示します。

## 今回の実施方法

導入済みのグローバル方針を確認した主担当が、次の仕事を別コンテキストで委任しました。

| 仕事 | 担当範囲 | 制約 |
|---|---|---|
| 方針設計の監査 | 委任判断、モデル選択、権限、独立検証 | 読み取り専用 |
| 導入処理の監査 | Windows、パス、バックアップ、更新手順 | 本体は読み取り専用。再現は指定fixtureのみ |
| 修正後の独立検証 | 修正差分、ハードリンク検出、両エンジン、自動テスト | 読み取り専用 |

各起動で`gpt-6.1-sol` / `high`を指定しました。安全性・複数段階の設計判断を含むための選択で、固定的な役割設定にはしていません。起動、調査、結果の受領は確認しました。バックエンドで実際に採用されたモデル・推論強度を裏付ける実行時情報は取得していないため、実適用値は未確認です。

主担当が指摘のコードと再現結果を確認し、修正・テスト・公開を担当しました。レビュー担当は本体ファイルを並行編集していません。Git更新手順のテストには独立したローカルGitリポジトリと架空の配置先を使用します。

## 採用した改善

1. **利用できない委任機能への対応**：ツールが対応する設定・コンテキスト継承に従い、モデル指定不可なら既定値を引き継ぐ。委任不可なら可能な範囲を直接進め、制約を報告する。
2. **権限範囲の明示**：子への依頼に担当ファイルと許可操作を含める。委任によって権限を広げず、既に承認された範囲は引き継ぐ。
3. **ハードリンクからの認証情報複製を防止**：従来はAGENTS.mdがauth.jsonのハードリンクでも、バックアップを作成できた。配布元・配布先のリンク数をWindowsのファイルメタデータで確認し、ハッシュ・バックアップ前に拒否する。認証ファイルの実物を使わず再現・検証した。
4. **従来の日本語コンソールへの対応**：更新時のGitルート確認を、UTF-8のパス文字列比較からASCIIの作業ツリー判定・ルートからの相対位置判定へ変更した。
5. **未公開の方針の誤配布を防止**：`pull --ff-only`が成功してもローカルmainが先行する場合がある。HEADと取得したFETCH_HEADの一致を確認し、不一致なら導入しない。
6. **両PowerShellの継続検証**：テスト内部のWindows PowerShell固定起動を解消。呼び出したエンジンで導入・検証を実行し、Windows上の両エンジンをGitHub Actionsにも追加した。成功時の終了コードを明示して、想定エラー検証後もCIを誤失敗させない。

## 確認結果と限界

- Windows PowerShell 5.1およびPowerShell 7.6.5で回帰テストが成功。
- 任意CWD、日本語・空白・角括弧パス、初回配置、同一内容、差分停止、WhatIf、Forceの空/非空バックアップ、バックアップ失敗時の保持を確認。
- 架空のconfig.toml・auth.jsonの保持、配布元と配布先のハードリンク拒否、バックアップ未作成、ジャンクション拒否、相対パス拒否、BOM・構文を確認。
- READMEから抽出した更新ブロックをPS5.1・CP932・日本語/空白パスの独立したローカルGit環境で検証。同期済みは導入・検証へ進み、ローカル先行・未追跡変更・想定外originは導入前に停止した。導入・検証は到達確認用スタブであり、実ファイル配置の確認は別の回帰テストで実施した。取得失敗・リモートより古い状態の更新・検証失敗を組み合わせた統合テストは未実施。
- CIと同じ呼び出し形式でも、PS5.1で全件成功後の終了コード0を確認した。GitHub上のCI結果は各コミットのActionsで確認する。
- 複数の実際の調査をサブエージェントへ委任し、独立レビューから具体的な改善につながった。ファイル一致だけを委任動作の証拠にはしていない。
- 既存の実設定・認証情報は読み取り・変更していない。今回の方針本文の改善はリポジトリ側に保存し、実際のグローバルAGENTS.mdは自動置換していない。適用するときはREADMEの差分確認・バックアップ付き導入を使う。
- PowerShellの制約付き言語モードなど、ファイルメタデータ検査を実行できない環境では安全側に停止する。共有先ファイルシステムすべての互換性は保証しない。
